# ゲームのルール

---

## チェイサーゲームの基本

**目的**: マップ上のアイテムを集めて得点を競う

**プレイヤーの行動サイクル**:
```
getReady() → コマンド実行 → getReady() → コマンド実行 → ...
```

1. **getReady()**: 周囲3x3の状況を把握
2. **コマンド実行**: walk（移動）、look（遠方確認）、search（周辺探索）など
3. これを交互に繰り返す

---

## getReady()で得られる情報

**3x3の範囲**（常に絶対座標基準、北が上）

```
[UL][U ][UR]
[L ][P ][R ]  ← プレイヤーの周囲9マス
[DL][D ][DR]
```

**各マスの情報**:
- **EMPTY**: 空マス（移動可能）
- **BLOCK**: 壁（移動不可）
- **ITEM**: アイテム（取得可能）
- **ENEMY**: 敵（避けるべき）

---

## 利用可能なコマンド

### walk(direction)
指定方向に1マス移動
- direction: `"up"`, `"down"`, `"left"`, `"right"`

### その他のコマンド（今回は未使用）
- **look(direction)**: 指定方向の遠方を確認
- **search()**: 周辺をより広く探索
- **put()**: アイテムを置く

**このアルゴリズムでは、主にwalkコマンドを使用**

# 従来手法の課題
その場判断の限界

---

## その場判断アルゴリズムとは

**現在見えている3x3の範囲だけで判断**

```
[ ][ ][ ]
[ ][P][ ]  ← この9マスだけを見て次の行動を決定
[ ][ ][ ]
```

- 目の前のアイテムや未探索マスに反応
- 「今見えているもの」だけで評価
- 将来の結果を考慮しない

---

## 問題: 抜け道を見過ごす

```
BBBBBBBBB
B   ←P→ B  ← 左右に空マスが見える
BBBB↓BBBB  ← 下に抜け道があるが気づかない
     
   [脱出]
```

**その場判断の動き**:
1. 左右に空マスが見える → 左へ移動
2. また左右に空マスが見える → 右へ移動
3. 永遠に左右を往復してしまう

**問題点**:
- 下方向に抜け道があっても気づかない
- 目の前の左右の空マスにしか反応できない
- 同じエリアを延々と往復し続ける（無限ループ）

---

## 先読みの必要性

❌ **その場判断**: 「今見えているもの」だけで判断
✅ **先読み思考**: 「この行動の先に何があるか」を考える

**10手先まで読む重要性**:
- 袋小路を事前に検出
- 無駄な往復を避ける
- 計画的にアイテムを回収
- 効率的な探索経路を選択

---

# アルゴリズムの概要

---

## 3つの核心要素

### 1. **記憶** - 地図情報の蓄積
- ゲーム中に得た情報を絶対座標系で記録
- 探索が進むほど賢くなる

### 2. **先読み** - 深度10の4分木探索
- 10手先までシミュレーション
- 理論上100万パターン → 枝刈り後は数百〜数千

### 3. **実行** - 計画継続システム
- 一度決めた計画を最後まで実行
- フラフラせず、目標に向かって直進

# シンプルな点数システム

---

## 各マスの評価

| マスの種類 | 点数 | 説明 |
|-----------|------|------|
| **アイテム（ITEM）** | **+2点** | 最優先で獲得 |
| **未探索** | **+1点** | 探索を促進 |
| **空マス（EMPTY）** | **0点** | 移動可能だが価値なし |
| **ブロック（BLOCK）** | **-∞** | 移動不可、このルートは枝刈り |

**なぜシンプルなのが効果的か**:
- 明確な優先順位
- 計算が高速
- 経路上の合計で評価

# 4分木探索

---

## 4分木探索の基本

**各ノードで4方向を評価**:
1. 上（up）: 北方向への移動
2. 下（down）: 南方向への移動
3. 左（left）: 西方向への移動
4. 右（right）: 東方向への移動

**深度10の意味**:
- 10手先までシミュレーション
- 理論上 4^10 = **1,048,576パターン**
- 実際は枝刈り後 **数百〜数千パターン**

---

## 探索ツリーの構造

```
ルートノード (現在位置)
├─ up (1手目)
│  ├─ up (2手目) ※down は枝刈り（往復防止）
│  │  ├─ up (3手目)
│  │  ├─ left (3手目)
│  │  └─ right (3手目)
│  ├─ left (2手目)
│  └─ right (2手目)
├─ down (1手目)
├─ left (1手目)
└─ right (1手目)
```

各リーフノードまでの経路スコアを計算 → 最高得点を選択

---

<!-- _class: lead -->
# 枝刈りの仕組み

---

## 2つの枝刈りルール

### 1. **移動不可の枝刈り**
- ブロック（BLOCK）への移動
- 敵（ENEMY）への移動
→ このパスは `-∞` として即座に排除

### 2. **往復パスの枝刈り**（重要！）
- 同じ経路内で既に訪れた位置に戻るパスを排除
- 例: `up → down → up` のような往復パターンを防止

**効果**: 100万パターン → 数百〜数千パターンに削減

---

## 往復パス枝刈りの例

### ❌ 枝刈り前
```
up → down → up → down → up → down
（同じ2マスを延々往復）

評価パターン数: 膨大
```

### ✅ 枝刈り後
```
up → down  ← ここで打ち切り
（既に訪問済みの位置に戻るため枝刈り）

評価パターン数: 大幅削減
```

---

## 豆知識：完全4分木ではない

**往復パス枝刈りの効果**

枝刈りにより、各ノードが必ずしも4つの子を持つわけではない：

```
ルートノード
├─ up (1手目) ← 4つの子
│  ├─ up (2手目) ← 3つの子（downは枝刈り）
│  ├─ left (2手目)
│  └─ right (2手目)
├─ down (1手目)
├─ left (1手目)
└─ right (1手目)
```

**正確には**: 「最大4分木」または「4方向探索木」
- 完全4分木: 各ノードが必ず4つの子を持つ
- このアルゴリズム: 各ノードが最大4つの子を持つ（枝刈りで減少）

# 計画継続システム
アルゴリズムの最大の特徴

---

## 計画継続とは

**一度立てた計画を最後まで実行する**

### 動作フロー
1. **計画立案**: 4分木探索で10手先までの最適経路を選択
2. **最初の行動実行**: 計画の1手目を実行
3. **残りを保存**: 計画の2〜10手目を保存
4. **次ターン**: 敵がいなければ、再探索せずに計画の2手目を実行
5. **継続**: 計画が尽きるか、敵に遭遇するまで継続

---

## 計画破棄の条件

以下の場合のみ計画を破棄して再探索:

1. **敵遭遇**: 8方向（上下左右+斜め）に敵を検出
2. **計画が危険**: 次の計画行動がブロックや敵になっている

それ以外は**計画を実行し続ける**

---

## 計画継続の4つのメリット

### 1. **一貫性**
フラフラせず、目標に向かって直進

### 2. **効率性**
毎ターン深度10の探索をしなくて済む

### 3. **計画性**
10手先を見据えた戦略を実際に遂行

### 4. **反応性**
危険を検知したら即座に計画変更

---

## 動作例（タイムライン）

```
ターン1: 4分木探索（深度10）
       → 最適経路["right", "right", "up", "up", ...]
       → "right"に移動、残りを保存
       📊 評価した経路数: 1247パターン

ターン2: 敵なし、計画実行
       → "right"に移動
       ⏭️  探索スキップ（計画実行中）

ターン3: 敵なし、計画実行
       → "up"に移動
       ⏭️  探索スキップ（計画実行中）

ターン4: 敵を検出！
       → 計画破棄、逃げる
       ⚠️  緊急回避モード

ターン5: 敵なし、計画なし
       → 4分木探索（深度10）→ 新しい計画を立案
       📊 評価した経路数: 892パターン
```

# 実装から得られた学び

---

## 2つの重要な発見

### 1. **計画継続の重要性**
- 毎ターン再探索すると往復問題が発生
- 計画を最後まで実行することで解決

### 2. **往復パスの枝刈り**
- `up → down → up`のような無駄を削減
- 評価パターン数を大幅に削減

---

## 探索深度の拡張経緯

**当初**: 深度3（理論上64パターン）
- 限定的な先読み
- 短期的な判断のみ

**最終**: 深度10（理論上100万パターン）
- 往復枝刈りにより実現可能に
- より長期的な戦略が可能
- 計画継続により探索コストを実質削減
